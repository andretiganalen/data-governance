# DG workspace — notes for coding agents

- Len Data Governance deploy lives in `deploy/lendatagovernance` (live copy: `/opt/lendatagovernance/deploy`, data: `/srv/lendatagovernance`). Plan: `plan/lendatagovernance_deployment_plan.md`.
- Naming (user rule 2026-11-10): no "OpenMetadata"/"OM" names anywhere we control — services `ldg-server`/`ldg-migrate`, DB `lendatagovernance_db`, env `LDG_DATA_DIR`, token `LDG_TOKEN`, loaders `loader/catalog_loader.py` + `loader/catalog_trino.py`, SSO `superset/dg_sso.py` (cookie `dg_token`). Only upstream-fixed names remain (image `docker.getcollate.io/openmetadata/server`, in-image paths, env keys like `OPENMETADATA_*`/`OM_DATABASE`, API/URL paths); UI text is rebranded by the gateway + `leno-menu.js`.
- UI default for every web app: `plan/interface-menu.md` (Len classic: colours, fonts, borders, menu from len.co.id). Positions: `plan/leno_interface_theme.md`.
- The DG Projects app (apps/web, packages/*) was removed on 2026-11-05; recover it from git history if ever needed.
- Data rule (2026-11-09, Andre Tigana): every database/dataset used by an app must live in the Trino lakehouse. Apps read and write their business data through Trino; no separate app databases, local files or CSV/XLSX stores as the system of record. Exception: a platform's own internal store that Trino cannot host (e.g. the catalog's and Superset's Postgres, OpenSearch). Raw CSV/XLSX files are Bronze input only (inbox), never a store users read from.
- Lakehouse: `lakekeeper.medallion_repository` on Trino `datahub.len.co.id:443`; table definitions in `deploy/lendatagovernance/medallion/schema/medallion_repository.sql` (source of truth, English skeleton naming), loader `medallion/lakehouse.py` (ingest/inbox/retry/rebuild/status). Credentials only in `/srv/lendatagovernance/secrets/trino.env` — never commit them (GitHub remote is public). The `/unduh/` file panel was closed 2026-11-10. ERM: the catalog's ERM tables are the Trino tables in `medallion_repository` (`loader/workbook.py` TABLE_MAP); old schemas `lakekeeper.erm*` copied in by `medallion/migrate_legacy_erm.py`; prototype `lakekeeper.medallion` moved into the SDM framework (`medallion/sdm.py`, `migrate_legacy_medallion.py`) and dropped. ERM source of truth for operational risks = Trino catalog `lenodb.silver` (LenO app CDC replica) via `medallion/leno_erm.py` (`_source_system = LENO_ERM`, beside EGRC rows). Asta Cita task-force data: Nextcloud `sharedrive.len.co.id` folder DBASTACITA → `medallion/nextcloud_sync.py` (app password in `secrets/nextcloud.env`, never print that file) → Bronze → `medallion/astacita.py` (join on theme code, not "Asta Cita N"). LenoDB data is refreshed by the 15-minute CDC timer (`lakehouse.py cdc`, watermarks in `lenodb.silver._cdc_watermarks`); freshness per Gold table in `gold_meta_data_freshness` (`medallion/freshness.py`). Users consume Gold only; valid numbers = Gold in Trino. User-created tables (Visualisasi/SQL Lab, all users) only in `lakekeeper.workspace`, enforced by `dg_sql_guard`; only Trino connections allowed.
- Visualisation is part of the main app (user rules 2026-11-09): menu Visualisasi opens an in-app panel (`deploy/ui/leno-theme/leno-menu.js`) showing Superset 6 (`:8585/visualisasi/`, SUPERSET_APP_ROOT) without Superset chrome; login is SSO from the Len Data Governance session (`superset/dg_sso.py`), no Superset passwords; theme = LenO (`leno-superset.css`).

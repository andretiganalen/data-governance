# DG workspace — notes for coding agents

- Len Data Governance deploy lives in `deploy/lendatagovernance` (runs directly from this repo; data + secrets in `data/`, git-ignored; since 2026-11-11 nothing lives in /opt or /srv). Plan: `plan/lendatagovernance_deployment_plan.md`.
- Naming (user rule 2026-11-10): no "OpenMetadata"/"OM" names anywhere we control — services `ldg-server`/`ldg-migrate`, DB `lendatagovernance_db`, env `LDG_DATA_DIR`, token `LDG_TOKEN`, loaders `loader/catalog_loader.py` + `loader/catalog_trino.py`, SSO `superset/dg_sso.py` (cookie `dg_token`). Only upstream-fixed names remain (image `docker.getcollate.io/openmetadata/server`, in-image paths, env keys like `OPENMETADATA_*`/`OM_DATABASE`, API/URL paths); UI text is rebranded by the gateway + `leno-menu.js`.
- UI default for every web app: `plan/interface-menu.md` (UIx since 2026-11-11, user decision: red `#ae2524`, Poppins, radius 8/12, grey-first; the only theme, old styles removed; fonts in `deploy/ui/leno-theme/fonts/`).
- The DG Projects app (apps/web, packages/*) was removed on 2026-11-05; recover it from git history if ever needed.
- Data rule (2026-11-09, Andre Tigana): every database/dataset used by an app must live in the Trino lakehouse. Apps read and write their business data through Trino; no separate app databases, local files or CSV/XLSX stores as the system of record. Exception: a platform's own internal store that Trino cannot host (e.g. the catalog's and Superset's Postgres, OpenSearch). Raw CSV/XLSX files are Bronze input only (inbox), never a store users read from.
- Lakehouse: `lakekeeper.medallion_repository` on Trino `datahub.len.co.id:443`; table definitions in `deploy/lendatagovernance/medallion/schema/medallion_repository.sql` (source of truth, English skeleton naming), loader `medallion/lakehouse.py` (ingest/inbox/retry/rebuild/status). Credentials only in `/home/ubuntu/data-governance/data/secrets/trino.env` — never commit them (GitHub remote is public). The `/unduh/` file panel was closed 2026-11-10. ERM: the catalog's ERM tables are the Trino tables in `medallion_repository` (`loader/workbook.py` TABLE_MAP); old schemas `lakekeeper.erm*` copied in by `medallion/migrate_legacy_erm.py`; prototype `lakekeeper.medallion` moved into the SDM framework (`medallion/sdm.py`, `migrate_legacy_medallion.py`) and dropped. ERM source of truth for operational risks = Trino catalog `lenodb.silver` (LenO app CDC replica) via `medallion/leno_erm.py` (`_source_system = LENO_ERM`, beside EGRC rows). Asta Cita task-force data: Nextcloud `sharedrive.len.co.id` folder DBASTACITA → `medallion/nextcloud_sync.py` (app password in `secrets/nextcloud.env`, never print that file) → Bronze → `medallion/astacita.py` (join on theme code, not "Asta Cita N"). LenoDB data is refreshed by the 15-minute CDC timer (`lakehouse.py cdc`, watermarks in `lenodb.silver._cdc_watermarks`); freshness per Gold table in `gold_meta_data_freshness` (`medallion/freshness.py`). Users consume Gold only; valid numbers = Gold in Trino. User-created tables (Visualisasi/SQL Lab, all users) only in `lakekeeper.workspace`, enforced by `dg_sql_guard`; only Trino connections allowed.

- Language (2026-11-12): the app's language menu has "Bahasa Indonesia - ID" (formal Indonesian, never mixed with English in one view). Gateway `sub_filter`s on the main bundle register `id-ID` and load `/_leno/i18n/id-id.js`, built by `deploy/ui/leno-theme/i18n/build.py` from `i18n/id-id.json` (source to edit: keys as in en-US `label`/`message`/`server`; untranslated keys fall back to English). Superset (Visualisasi) follows the same language (2026-11-12): image `lendatagovernance/superset:6.0.0-dg3` builds the `id` pack from `superset/translations/id.json` (4347 texts: 4036 from the image's messages.pot + 311 used by the frontend but missing from the .pot) with `superset/translations/build_id.py` (.po/.mo/messages.json); `superset_config.py` sets `LANGUAGES={en,id}` and `dg_sso._lang()` sets `session["locale"]` from cookie `i18next` on every request (Superset's own language picker is hidden by CSS). - Catalog layers (2026-11-11, merged 2026-11-12 by user decision: ONE classification, no own terms): every table carries the app's built-in `Certification.Bronze|Silver|Gold` (the `certification` field, set by `loader/catalog_trino.py` from the table-name layer; new Trino tables adapt to Certification, never the other way). The old own classification `LapisanData` was removed. Global `assetCertificationSettings.validityPeriod` = `P3650D` (default P30D would expire layers); sync re-applies when < 180 days remain. Policy `SembunyikanLapisanMentah` (on the Organization team, condition `matchAnyCertification('Certification.Bronze','Certification.Silver') && !inAnyTeam('UV-1')`) denies viewing Bronze/Silver to everyone except admins/loader and members of team UV-1. Search is access-controlled too (2026-11-12: `searchSettings.globalSettings.enableAccessControl = true`; before it was false, so Bronze/Silver names showed in Explore; to roll back set it back to false via PUT /system/settings). - Glossary two-way rule (2026-11-11): Admin Data Governance (team UV-1, role `AdminDataGovernance`) edits Glossary/Fungsi in the app; the app is then the source. `medallion/glossary_app.py` records terms into Gold `gold_meta_glossary_app` (the older Gold `gold_meta_glossary` is the Workbook dashboard table, untouched) (timer `lendatagovernance-glossary`, 10 min, also at end of `rebuild`; `sumber_perubahan` = Workbook|Aplikasi). - Fungsi two-way rule (2026-11-11): admin DG may add/rename/remove Fungsi teams (`FN_*`) in the app; `medallion/glossary_app.py build_fungsi` records them into Gold `gold_meta_fungsi` (same 10-min timer, also at end of `rebuild`; must equal the app's FN_* list). - Glossary "Organisasi dan Fungsi" (2026-11-11, user decision): holds Fungsi Generik (one child term per `FN_*` team, definition read at runtime from CLP-001 in `data/referensi/` — never commit definitions), Struktur Organisasi Saat Ini and Kadaluarsa (from `silver_dim_organization`, SCD2). - Trash rule (2026-11-11, user decision): Owner-Rule keeps Delete, but nothing is deleted at once. Gateway (`gateway/nginx.conf`, `$ldg_api_uri`) rewrites `DELETE ...hardDelete=true` to `hardDelete=false` for network clients (only the server itself — 127.0.0.1 / 172.28.11.1 — may hard delete), so every delete = soft delete (Trash, restorable). `medallion/trash_purge.py` (timer `lendatagovernance-trash`, daily 02:30, units in `host/systemd/`, installed by the user with sudo) hard-deletes entities soft-deleted > 20 days. UI (`deploy/ui/leno-theme/leno-trash.js`): Indonesian "Pindahkan ke Tempat Sampah?" dialog explaining effects and risks in a calm tone (no alarm colours, permanent option hidden) and card "Tempat Sampah" (recycle icon) in Settings (list, days left, Pulihkan; moved from the sidebar 2026-11-12). After editing `gateway/nginx.conf` ALWAYS `docker compose up -d --no-deps --force-recreate gateway` (an in-place edit + `nginx -s reload` did not reach the container on 2026-11-13).

- Documents file store (2026-11-12): the catalog only supports S3/Azure/in-memory storage for Context Center files (no local-disk provider). Without a store every upload showed `Failed` ("Unable to read file content from object storage") and could not be downloaded ("No current content found for this file"). Fix: one internal container `ldg-storage` (SeaweedFS 3.85 S3, bucket `ldg-files`, no published port, data in `data/storage`, keys in `data/secrets/storage.env` + `storage-s3.json`, never commit); `ASSET_UPLOADER_*` in `lendatagovernance.base.env`; `AWS_REQUEST_CHECKSUM_CALCULATION=when_required` is mandatory (otherwise SeaweedFS stores aws-chunked framing and downloads are corrupt). Downloads: the API 307-redirects to a presigned `http://ldg-storage:8333/...` URL; the gateway rewrites it with `proxy_redirect` to `/_ldgstore/` (GET/HEAD only, Host must stay `ldg-storage:8333`, gateway also sits on `ldg-internal`). MinIO was the plan but its public images are gone. `backup.sh` tars `data/storage`; migrating to a new server = copy `data/` + this repo. Files uploaded before the fix have no content: delete and re-upload (`referensi-sinkron.py` re-uploads Reference from `data/referensi`). ERM folder's 2 older files are still empty until re-uploaded from the original.
- Update status + NULL rule (2026-11-12, user rules): `gold_meta_data_freshness` now has `update_status` (`Diperbarui` = Gold content changed within 7 days | `Eksisting` = no change; never NULL) + `update_status_en` (`Updated`|`Existing`), `update_note`/`update_note_en`, `last_changed_at`, `previous_row_count`, `content_fingerprint` (Trino `checksum(ROW(non-lineage cols))`, previous state is read before `ensure_table` recreates the table; first check = Eksisting baseline). Same-checksum Excel files are skipped at Bronze ("sudah pernah dimuat") = Eksisting. E-GRC/any source: empty stays NULL, nothing invented: `lakehouse.py comp()` no longer substitutes DEFEND ID (`DID`) when Entity is empty (`company_id`/name/acronym NULL; `company_id_is_assumed` = "Entity empty in source"). ERM/E-GRC Excel in `docs/bronze/` (not in git) are uploaded to Documents > ERM with `scripts/referensi-sinkron.py ERM docs/bronze "<file>" ...` (reference/download copy only; Gold in Trino stays the valid numbers).

- Export Excel (2026-11-12): `medallion/export_xlsx.py` writes Gold `gold_meta_*` (dictionary, glossary, DQ rules, lineage, access) to one Excel, header UIx red, hidden `Library` dropdown; static cell colours: RED = required column empty/"Belum ada"/"Perlu input manual…", YELLOW = should-be-filled column empty; NULL stays NULL. `--filter TEXT` limits to fields whose owner/steward/user unit contains TEXT (callers must pass the user's access scope; no filter = admin only). Output in `data/exports/` (git-ignored). UI (2026-11-12): card "Unduh Excel" in Settings (`leno-trash.js`, texts in `leno-i18n.js`) → gateway `/_export/` → container `ldg-export` (`medallion/export_server.py`, image `lendatagovernance/export:1`, runs as uid 1003 because `trino.env` is mode 600, internal+egress networks; code bind-mounted, restart to pick up changes). It validates the session Bearer token against ldg-server `/users/loggedInUser`: download allowed = isAdmin | team UV-1 | team Pengunduh | any FN_* team (level 5 Lihat saja: 403); scope = all for isAdmin/UV-1, otherwise elements whose owner/steward/user units contain an ORG_ID of the user's Fungsi (FN_* → `silver_dim_organization` by name) or of unit teams named like `UG-1`. Users are not yet mapped to units (P3-3), so a plain Pengunduh account gets an empty workbook. Every download is logged (user, scope, row counts; no data). Table creation in the catalog UI does NOT create a Trino table (sync is Trino → catalog and soft-deletes tables missing in Trino); a "Create table" form that runs CREATE TABLE in `lakekeeper.workspace` is still to be built. Fungsi (owner, `FN_*`) ≠ Domain (data subject area, `BUSINESS_DOMAIN`; no Domain objects in the app yet). Workflow infographic: `docs/infografis/alur-kerja-aplikasi.html`.
- Cookie size (2026-11-12): cookies are shared per IP across ports/apps, so browsers can send >8 KB. Gateway has `large_client_header_buffers 4 32k` (else nginx 400 "Request Header Or Cookie Too Large") and a `map $http_cookie $ldg_cookie` that drops a Cookie header > 5000 chars before proxying to ldg-server (Jetty answers 431 above its 8 KiB header limit; the app uses Bearer tokens, not cookies). Alternative if ever needed: env `SERVER_MAX_REQUEST_HEADER_SIZE` on ldg-server (needs restart).
- Audit 2026-11-13 (12 iterations): the Glossary was renamed in the app to `Fungsi Organisasi` (display "Fungsi"), code constants follow it (`glossary_org.GLOSSARY`, `fungsi_pdf.PARENT`). Gateway: edits to `gateway/nginx.conf` were NOT picked up by `nginx -s reload` (container held an old inode); always `docker compose up -d --no-deps --force-recreate gateway`. Trash rule hardened (case-insensitive, duplicate params, `%`-encoded query from network clients = 400). Never put `count(DISTINCT IF(..))` next to other aggregates in Trino SQL (OPTIMIZER_TIMEOUT 500 s hung the glossary timer). systemd units now carry `TimeoutStartSec` (repo copies only; user must reinstall with sudo + daemon-reload). `ldg-storage` healthcheck uses `ldg-storage:8888` (localhost never answered, so it was permanently unhealthy and blocked `compose up` of dependents); backup tars `data/storage` inside the container (root-owned files). `docker compose up -d <svc>` pulls dependencies: use `--no-deps` for single-service restarts.

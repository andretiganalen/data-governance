# DG workspace — notes for coding agents

- Len Data Governance deploy lives in `deploy/lendatagovernance` (runs directly from this repo; data + secrets in `data/`, git-ignored; since 2026-11-11 nothing lives in /opt or /srv). Plan: `plan/lendatagovernance_deployment_plan.md`.
- Naming (user rule 2026-11-10): no "OpenMetadata"/"OM" names anywhere we control — services `ldg-server`/`ldg-migrate`, DB `lendatagovernance_db`, env `LDG_DATA_DIR`, token `LDG_TOKEN`, loaders `loader/catalog_loader.py` + `loader/catalog_trino.py`, SSO `superset/dg_sso.py` (cookie `dg_token`). Only upstream-fixed names remain (image `docker.getcollate.io/openmetadata/server`, in-image paths, env keys like `OPENMETADATA_*`/`OM_DATABASE`, API/URL paths); UI text is rebranded by the gateway + `leno-menu.js`.
- UI default for every web app: `plan/interface-menu.md` (UIx since 2026-11-11, user decision: red `#ae2524`, Poppins, radius 8/12, grey-first; the only theme, old styles removed; fonts in `deploy/ui/leno-theme/fonts/`).
- The DG Projects app (apps/web, packages/*) was removed on 2026-11-05; recover it from git history if ever needed.
- Data rule (2026-11-09, Andre Tigana): every database/dataset used by an app must live in the Trino lakehouse. Apps read and write their business data through Trino; no separate app databases, local files or CSV/XLSX stores as the system of record. Exception: a platform's own internal store that Trino cannot host (e.g. the catalog's and Superset's Postgres, OpenSearch). Raw CSV/XLSX files are Bronze input only (inbox), never a store users read from.
- Lakehouse: `lakekeeper.medallion_repository` on Trino `datahub.len.co.id:443`; table definitions in `deploy/lendatagovernance/medallion/schema/medallion_repository.sql` (source of truth, English skeleton naming), loader `medallion/lakehouse.py` (ingest/inbox/retry/rebuild/status). Credentials only in `/home/ubuntu/data-governance/data/secrets/trino.env` — never commit them (GitHub remote is public). The `/unduh/` file panel was closed 2026-11-10. ERM: the catalog's ERM tables are the Trino tables in `medallion_repository` (`loader/workbook.py` TABLE_MAP); old schemas `lakekeeper.erm*` copied in by `medallion/migrate_legacy_erm.py`; prototype `lakekeeper.medallion` moved into the SDM framework (`medallion/sdm.py`, `migrate_legacy_medallion.py`) and dropped. ERM source of truth for operational risks = Trino catalog `lenodb.silver` (LenO app CDC replica) via `medallion/leno_erm.py` (`_source_system = LENO_ERM`, beside EGRC rows). Asta Cita task-force data: Nextcloud `sharedrive.len.co.id` folder DBASTACITA → `medallion/nextcloud_sync.py` (app password in `secrets/nextcloud.env`, never print that file) → Bronze → `medallion/astacita.py` (join on theme code, not "Asta Cita N"). LenoDB data is refreshed by the 15-minute CDC timer (`lakehouse.py cdc`, watermarks in `lenodb.silver._cdc_watermarks`); freshness per Gold table in `gold_meta_data_freshness` (`medallion/freshness.py`). Users consume Gold only; valid numbers = Gold in Trino. User-created tables (Visualisasi/SQL Lab, all users) only in `lakekeeper.workspace`, enforced by `dg_sql_guard`; only Trino connections allowed.
- Branding (2026-11-12, hardcoded): logo = Len Holding of DEFEND ID (`docs/template/logo len holding of defend id.png` → `deploy/ui/leno-theme/brand/`). The gateway serves `/api/v1/system/config/customUiThemePreference` from `brand/theme.json` (GET only) and `/favicon.png` from `brand/`, because the upstream public endpoint returned empty logo URLs (= default upstream logo). Settings card icons (Tempat Sampah = dark-grey trash can with recycle; Preferences = red UIx theme/palette) are drawn in `leno-trash.js`. Change logo only by replacing files in `brand/`.
- Language (2026-11-12): the app's language menu has "Bahasa Indonesia - ID" (formal Indonesian, never mixed with English in one view). Gateway `sub_filter`s on the main bundle register `id-ID` and load `/_leno/i18n/id-id.js`, built by `deploy/ui/leno-theme/i18n/build.py` from `i18n/id-id.json` (source to edit: keys as in en-US `label`/`message`/`server`; untranslated keys fall back to English). Status 2026-11-12: all 2927 `label`, 1497 `message` and 85 `server` keys translated (formal; term glossary in `i18n/glosarium.md`, "OpenMetadata" replaced by "Len Data Governance"). Not translated: Superset (Visualisasi) UI, data content (table/column names, descriptions), and any string hardcoded in the upstream bundle outside i18n. To fix a term: edit `i18n/id-id.json`, run `python3 i18n/build.py`. Our own injected texts (Explore/Visualisasi menu, Tempat Sampah, delete dialog) live in `leno-i18n.js` (ID/EN dictionaries, follows cookie `i18next`; add every new custom string there, never hardcode one language). Superset UI language is separate (not yet translated).
- Documents folders (2026-11-12): ERM and Reference are treated alike (both hold files; folders are flat, no tree in this version — folder tree is under consideration). `deploy/ui/leno-theme/leno-docs.js` (injected by the gateway) sorts the Documents API responses: folders in manual order (`FOLDER_ORDER`), files descending by created date parsed from the file name (`YYMMDD CC Nama`), and shows "Created YYMMDD" in the small line (updatedAt is not reliable: it changes on move/processing).
- UI standard for custom pieces (2026-11-12, user rule): build new menus/cards/pages from the app's own classes and structure (ant-card, page-header-container, ant-table, ant-btn, native-style 89px card SVG icons, sidebar children as `<a class="left-panel-item…">`), placed with `main.ant-layout-content`; never hand-styled lookalikes. Compare against the sibling in the same menu before shipping.
- Visualisation is part of the main app (user rules 2026-11-09): menu Explore is a dropdown (Explore, Visualisasi; since 2026-11-12) and Visualisasi opens an in-app panel (`deploy/ui/leno-theme/leno-menu.js`) showing Superset 6 (`:8585/visualisasi/`, SUPERSET_APP_ROOT) without Superset chrome; login is SSO from the Len Data Governance session (`superset/dg_sso.py`), no Superset passwords; theme = LenO (`leno-superset.css`). Never expose a separate port or credential. After syncing `gateway/nginx.conf` to /opt, `docker compose up -d --force-recreate gateway` (file bind-mount). Reply to the user in Bahasa Indonesia.
- Catalog layers (2026-11-11, merged 2026-11-12 by user decision: ONE classification, no own terms): every table carries the app's built-in `Certification.Bronze|Silver|Gold` (the `certification` field, set by `loader/catalog_trino.py` from the table-name layer; new Trino tables adapt to Certification, never the other way). The old own classification `LapisanData` was removed. Global `assetCertificationSettings.validityPeriod` = `P3650D` (default P30D would expire layers); sync re-applies when < 180 days remain. Policy `SembunyikanLapisanMentah` (on the Organization team, condition `matchAnyCertification('Certification.Bronze','Certification.Silver') && !inAnyTeam('UV-1')`) denies viewing Bronze/Silver to everyone except admins/loader and members of team UV-1. Search is access-controlled too (2026-11-12: `searchSettings.globalSettings.enableAccessControl = true`; before it was false, so Bronze/Silver names showed in Explore; to roll back set it back to false via PUT /system/settings). Silver tables must carry a Bahasa Indonesia comment (`medallion/silver_comments.py`, run at the end of `rebuild`).
- Reference documents (CLP-001, CLP-002, …) live in `data/referensi/` (not in git: internal "uncontrolled" Len documents), named `YYMMDD CC Nama.ext`; add with `scripts/referensi-tambah.py "<file>=<Nama>"` (CC = next upload number). Served only to logged-in users at `/referensi/` (gateway `auth_request`; the sidebar item "Referensi" was removed 2026-11-12: documents now live in Context Center > Documents > folder `Reference`, filled automatically by `scripts/referensi-sinkron.py`, called at the end of `referensi-tambah.py`; Documents folders are flat — the API has no sub-folders — so `Reference` sits beside `ERM`). Data Owner = Fungsi (CLP-001, no "Fungsi" prefix, option A, applied 2026-11-11, `plan/data-owner-fungsi.md`): one Group team `FN_*` per Fungsi under its Division; Fungsi without a unit are named `<Fungsi> (tidak ada)`; unit teams (UG-1…) keep roles/membership, not ownership.
- Glossary two-way rule (2026-11-11): Admin Data Governance (team UV-1, role `AdminDataGovernance`) edits Glossary/Fungsi in the app; the app is then the source. `medallion/glossary_app.py` records terms into Gold `gold_meta_glossary_app` (the older Gold `gold_meta_glossary` is the Workbook dashboard table, untouched) (timer `lendatagovernance-glossary`, 10 min, also at end of `rebuild`; `sumber_perubahan` = Workbook|Aplikasi). Workbook reload (`scripts/reload-workbook.sh`, uses the venv python) never overwrites terms marked Aplikasi.
- Fungsi two-way rule (2026-11-11): admin DG may add/rename/remove Fungsi teams (`FN_*`) in the app; `medallion/glossary_app.py build_fungsi` records them into Gold `gold_meta_fungsi` (same 10-min timer, also at end of `rebuild`; must equal the app's FN_* list). Workbook reload keeps Fungsi renamed in the app.
- Glossary "Organisasi dan Fungsi" (2026-11-11, user decision): holds Fungsi Generik (one child term per `FN_*` team, definition read at runtime from CLP-001 in `data/referensi/` — never commit definitions), Struktur Organisasi Saat Ini and Kadaluarsa (from `silver_dim_organization`, SCD2). Created by `medallion/glossary_org.py` (create-if-missing only, never overwrites admin edits; runs in the 10-min glossary timer, so a new Fungsi gets a term automatically). Unknown/unsure content is written exactly "Perlu input manual dari Data Governance". Completeness stats go to Gold `gold_meta_glossary_status` (per term) and `gold_meta_glossary_ringkasan` (per glossary) via `glossary_app.build_status`: input for the Admin Data Governance to complete the Glossary. Gold `gold_meta_*` tables are owned by `FN_Tata_Kelola`.
- Trash rule (2026-11-11, user decision): Owner-Rule keeps Delete, but nothing is deleted at once. Gateway (`gateway/nginx.conf`, `$ldg_api_uri`) rewrites `DELETE ...hardDelete=true` to `hardDelete=false` for network clients (only the server itself — 127.0.0.1 / 172.28.11.1 — may hard delete), so every delete = soft delete (Trash, restorable). `medallion/trash_purge.py` (timer `lendatagovernance-trash`, daily 02:30, units in `host/systemd/`, installed by the user with sudo) hard-deletes entities soft-deleted > 20 days. UI (`deploy/ui/leno-theme/leno-trash.js`): Indonesian "Pindahkan ke Tempat Sampah?" dialog explaining effects and risks in a calm tone (no alarm colours, permanent option hidden) and card "Tempat Sampah" (recycle icon) in Settings (list, days left, Pulihkan; moved from the sidebar 2026-11-12). After editing `gateway/nginx.conf` edit IN PLACE (not `sed -i`/replace: the bind-mount keeps the old inode) or `docker compose up -d --force-recreate gateway`.
- Fungsi PDF (2026-11-11): `medallion/fungsi_pdf.py` (called from the 10-min glossary timer) publishes "Glosarium Fungsi Generik Rev NN" PDF into `data/referensi/` (via `scripts/referensi-tambah.py`, CC increments, old files kept) whenever a Fungsi term (name/definition/owner) changes; state + revision log in `data/medallion/fungsi_pdf_state.json`. Contains CLP-001 definitions: never commit it.

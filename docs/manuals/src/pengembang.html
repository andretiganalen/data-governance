§6Lakehouse Medallion dan Visualisasi

  
Aturan data: setiap dataset yang dipakai aplikasi hanya tinggal di Trino lakehouse 
  (datahub.len.co.id:443, Iceberg/Lakekeeper). Berkas CSV/XLSX hanya masukan Bronze sebelum ETL, bukan tempat pengguna membaca data.
  Postgres dan OpenSearch di stack ini hanya menyimpan status internal platform (katalog, Superset).

  

    
Loader

      
deploy/lendatagovernance/medallion/lakehouse.py: ingest, inbox, retry, rebuild, status.
      Skema tabel: medallion/schema/medallion_repository.sql (sumber kebenaran). build_medallion.py kini hanya menyediakan
      fungsi silver()/gold() untuk workbook dan tidak menulis berkas. Kredensial hanya di /home/ubuntu/data-governance/data/secrets/trino.env.

    
Inbox (masukan Bronze)

      
Letakkan berkas di /home/ubuntu/data-governance/data/medallion/inbox/. Timer systemd lendatagovernance-lakehouse-inbox.timer
      (tiap 10 menit) memuatnya ke Bronze, membangun ulang Silver/Gold, menyinkronkan katalog, lalu memindahkan berkas ke inbox/selesai/.
      Sumber dikenali: DG_WORKBOOK dan EGRC. Berkas lain hanya masuk Bronze (FILE).

  

  
Isi lakehouse saat rilis

  
Lapisan data = Certification (satu klasifikasi). Tiap tabel membawa Certification.Bronze|Silver|Gold menurut lapisannya,
    dipasang otomatis oleh loader/catalog_trino.py dari nama tabel; tabel Trino baru menyesuaikan diri ke Certification, tanpa klasifikasi buatan sendiri.
    Klasifikasi lama LapisanData sudah dihapus. Masa berlaku global assetCertificationSettings.validityPeriod = P3650D (bawaan P30D akan
    membuat lapisan kedaluwarsa) dan sinkron menerapkan ulang bila sisanya < 180 hari. Kebijakan SembunyikanLapisanMentah (tim Organization) menolak lihat Bronze/Silver bagi
    semua kecuali admin dan tim UV-1 dengan matchAnyCertification; pencarian juga berbasis hak akses (enableAccessControl = true), jadi Bronze/Silver tidak muncul di Explore pengguna biasa.
    Mengubah Certification tabel secara manual akan dikembalikan sinkron berikutnya.

Visualisasi (Superset 6 di dalam aplikasi)

  

    
AspekKetentuan

    
LetakMenu Visualisasi di sidebar membuka panel di area konten (ui/leno-theme/leno-menu.js), isi dari :8585/visualisasi/ (SUPERSET_APP_ROOT) di belakang gateway. Tidak ada port atau kredensial terpisah. Tema LenO: leno-superset.css.

    
LoginSSO dari sesi aplikasi: token sesi diteruskan ke cookie dg_token (path /visualisasi), diverifikasi superset/dg_sso.py. Admin → Admin; pengguna lain otomatis Gamma + sql_lab. Login kata sandi Superset dimatikan.

    
KoneksiHanya Trino. Koneksi basis data selain trino:// ditolak saat dibuat, diubah, atau diuji.

    
Tulis dataSemua pengguna boleh membuat tabel, hanya di schema lakekeeper.workspace: CREATE TABLE/CTAS/INSERT/UPDATE/DELETE/DROP pada workspace.<tabel> (nama schema wajib ditulis) dan unggah CSV/XLSX ke workspace. Tulis ke schema lain, termasuk medallion_repository milik loader, ditolak (dg_sql_guard, SQL_QUERY_MUTATOR).

    
Dashboard awalscripts/superset-setup.py membuat koneksi, dataset Gold, dan dashboard awal (login SSO memakai LDG_TOKEN).

§8Runbook operasi

  
Semua perintah dijalankan dari salinan live /home/ubuntu/data-governance/deploy/lendatagovernance (project compose lendatagovernance,
  layanan ldg-server, ldg-migrate, postgresql, opensearch, superset, gateway;
  jaringan ldg-internal/ldg-egress). Ubah di repo, lalu salin ke salinan live. Rencana: plan/lendatagovernance_deployment_plan.md.
  Setelan non-rahasia: lendatagovernance.base.env; rahasia: /home/ubuntu/data-governance/data/secrets/lendatagovernance.env
  (direktori data dapat diganti dengan LDG_DATA_DIR). Basis data katalog: lendatagovernance_db, role lendatagovernance_user
  (dibuat oleh postgres/init/10-lendatagovernance.sh).

  
Catatan: server katalog memakai image open-source upstream docker.getcollate.io/openmetadata/server:2.0.7;
  nama image, path di dalam image, kunci variabel lingkungan, dan path URL seperti /settings/... berasal dari upstream dan tidak dapat diganti namanya.


# kesehatan
sudo docker compose -p lendatagovernance ps ; scripts/verify.sh
curl -s http://127.0.0.1/_gateway/health
# mulai / henti / log
sudo docker compose -p lendatagovernance up -d ; sudo docker compose -p lendatagovernance stop
sudo docker compose -p lendatagovernance logs -f --tail=200 ldg-server
# terapkan perubahan gateway (nginx.conf = bind-mount berkas, jadi wajib recreate)
sudo docker compose -p lendatagovernance up -d --force-recreate gateway ; sudo docker compose -p lendatagovernance exec gateway nginx -t
# backup (timer harian 01:30 → /home/ubuntu/data-governance/data/backup, simpan 14 hari) dan pemulihan
sudo scripts/backup.sh
sudo docker compose -p lendatagovernance stop ldg-server
sudo docker compose -p lendatagovernance exec -T postgresql pg_restore -U postgres -d lendatagovernance_db --clean --if-exists \
  < /home/ubuntu/data-governance/data/backup/lendatagovernance_db-<YYYYMMDD-HHMM>.dump   # butuh lendatagovernance.env + jwt/ yang sama
sudo docker compose -p lendatagovernance start ldg-server   # lalu Settings › Applications › Search Indexing › Run
# token loader: profil admin › Access Token (60–90 hari) → LDG_TOKEN di secrets/loader.env
scripts/reload-workbook.sh "templates/<workbook>.xlsx"       # muat ulang katalog (catalog_loader.py) + selisih cacat
# lakehouse Trino (Bronze → Silver → Gold)
PY=/home/ubuntu/data-governance/data/medallion/.venv/bin/python; LH=medallion/lakehouse.py
cp "<berkas.xlsx>" /home/ubuntu/data-governance/data/medallion/inbox/  # dimuat timer dalam 10 menit
$PY $LH ingest "<berkas.xlsx>" ; $PY $LH retry ; $PY $LH rebuild ; $PY $LH status
$PY loader/catalog_trino.py                                  # sinkron katalog ↔ Trino (juga otomatis setelah pemuatan)
# Visualisasi (Superset 6)

$PY scripts/superset-setup.py [--force]                      # koneksi Trino + dataset + dashboard awal

  && sudo systemctl enable --now lendatagovernance-trash.timer   # sudah terpasang (harian 02:30)
# Glosarium "Organisasi dan Fungsi" + PDF Glosarium Fungsi Generik (ikut timer glosarium 10 menit)

Gangguan umum

  

    
GejalaPenyebab dan tindakan

    
Halaman "sedang memulai" (502/503)Server katalog (ldg-server) belum sehat. Cek ps/logs. OpenSearch butuh RAM: lihat mem_limit.

    
Loader: HTTP 401 "Expired token!"Token kedaluwarsa. Buat token baru dan simpan sebagai LDG_TOKEN (ST-8).

    
Lakehouse: galat commit/metadata LakekeeperSementara: loader mencoba ulang hingga 8 kali. Berkas berstatus PARTIAL dilengkapi dengan lakehouse.py retry. Bandingkan dengan lakehouse.py status.

    
Visualisasi meminta login atau kosongSesi aplikasi berakhir atau cookie dg_token belum terpasang: muat ulang aplikasi lalu buka menu Visualisasi lagi. Cek log superset.

    
SQL Lab: pernyataan tulis ditolakSesuai aturan: tulis hanya ke workspace.<tabel> dengan nama schema tertulis lengkap.

    
Pengguna biasa tidak melihat tabel Bronze/Silver di ExploreSesuai aturan: kebijakan SembunyikanLapisanMentah + pencarian berbasis hak akses. Staf DG (tim UV-1) dan admin melihatnya. Bila seorang staf tidak melihat, periksa keanggotaan tim UV-1.

    
Hapus tidak benar-benar menghapus / tidak ada pilihan hapus permanenSesuai aturan: setiap hapus dari klien jaringan menjadi soft delete (Tempat Sampah 20 hari, bisa dipulihkan di menu Tempat Sampah). Gateway mengubah hardDelete=true menjadi false ($ldg_api_uri di nginx.conf); hanya server sendiri yang boleh hapus permanen, lewat trash_purge.py.

    
Perubahan nginx.conf tidak berlakuBind-mount berkas menahan inode lama bila berkas diganti (sed -i). Ubah berkas di tempat, atau up -d --force-recreate gateway; periksa dengan exec gateway grep <kata> /etc/nginx/conf.d/default.conf.

    
Tema atau nama Len hilangMount ./ui/leno-theme atau sub_filter gateway berubah. Cek nginx -t.
